# 2026.331.0253 — feat(boxes): the ollama-cdi and ollama-rocm images and their beds

## Summary

Move the two ollama images and their two beds out of `distro-cachyos` into the repo that owns the
service (`AGENTS.md` "Repo classes and naming": a bed lives with the thing it tests; a `distro-*`
repo holds the distro family, not one service's box).

Three things change on the way in, each deliberate:

1. **The boxes compose the LOCAL `ollama` candy**, not a pinned release of this repo. A box in this
   repo must prove THIS tree; composing `@github.com/opencharly/pod-ollama:v2026.327.1941` would
   test a copy of the past, and the two boxes would name two different releases of the same repo.
   Measured (spike A below): with the remote refs, this repo's own two boxes resolve the candy at
   two git tags and the resolver emits its multi-tag notice. With the local candy, this repo's boxes
   contribute **zero** such notices.
   **Precisely scoped:** on the full project the pod-ollama notice is still visible, because the
   imported `cachyos` tree (pinned at `v2026.331.0132`) still carries its own copies of both boxes at
   the two old tags. It clears when the distro side deletes them — that is the follow-up PR, and this
   one does not claim to remove it.
2. **The project header declares what the distro copy inherited.** `base: cachyos` becomes
   `cachyos.cachyos` with the CachyOS base imported at the **project root** (a namespace mounted by
   a discovered document does not resolve a box's own `base:`), and
   `defaults.builder.{pixi,npm,cargo,aur}: arch.arch-builder` with the `arch` namespace imported (a
   builder map does not cross a namespace boundary). `podcdi` is imported for the CDI pod base.
3. **`AGENTS.md` gains the canonical-files entries this change creates**: `box/ollama-cdi/`,
   `box/ollama-rocm/` and the two beds, so the repo's own rulebook stays true about what it holds.
4. **The canonical `.gitignore` is added, copied verbatim from `distro-cachyos`.** This repo builds
   an image now, and `charly box build` writes `.build/`, `.check/`, `.containerignore` and
   `.dockerignore` into the project root. (Measured the hard way: the first attempt at this commit
   swept 512 `.build/` files in; it was reset and recommitted from explicit paths.)
