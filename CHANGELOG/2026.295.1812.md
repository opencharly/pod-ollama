# 2026.295.1812 — feat(skills): own the ollama-layer skill beside the candy it describes

## Summary

`ollama-layer` moves out of its **skills-only carrier** and into the repo that holds the code it
describes. Head `5c4f26b92a90b442b71a4b562f8b5aeacef84582`, 4 files, +171/-8.

`opencharly/layer-charly-ollama` is a concept candy whose entire content was one skill: a
`true`-no-op `plan:`, a `description:`, and a `skill:` node. Under the amended umbrella rulebook
(`AGENTS.md` Part II #5, the policy PR in this same session) that shape is retired — **a skill lives
in the repo whose code, plugin, or config it describes**, because a skill in a repo with no code
cannot be edited, reviewed, or tagged in the change that moves the thing it documents.

`ollama-layer` describes the `ollama` candy, and the `ollama` candy lives here. This repo's README
already advertised `/charly-ollama:ollama-layer` as its skill (line 75) — the prose was pointing at
a file that lived somewhere else. Now it does not.

### It is a MOVE, not a rewrite

- `sha256sum .agents/skills/ollama-layer/SKILL.md` is
  `e6e76bc4e04df25c369721e59bd432f9b559d0aef11a7d4915ff5b613d353cca` at **both** ends (the
  carrier's copy and this one).
- `diff -r layer-charly-ollama/.agents/skills/ollama-layer <this repo>/.agents/skills/ollama-layer`
  produced no output, exit 0.
- The frontmatter `name:` already equals the directory id, so nothing had to be edited to make it
  resolve here.

### The new node is routing-only

```yaml
ollama-layer-skill:
    skill:
        name: ollama-layer
        family: ollama
        owner: ollama
```

No inline `description:`/`content:`. A body inlined in a node can disagree with the file
(`plugin-marketplace/candy/plugin-marketplace/skillfile.go` refuses that state as a hard error), so
the moved body stays in its file and only the routing metadata is declared here. The node carries no
`triggers:`, so no `DISPATCHER.md` row is added or removed.
